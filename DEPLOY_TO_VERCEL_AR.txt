نشر نظام النسيم على Vercel باستخدام Express + Supabase

مهم:
- هذه الحزمة لا تحتوي على ملف .env أو مفاتيح سرية.
- اترك بيانات Supabase كما هي؛ لا تنفذ SQL أو تعِد استيراد البيانات.
- Vercel يتعرف على server.js كتطبيق Express. ملفات الواجهة موجودة داخل public/.
- تم حذف vercel.json القديم من هذه الحزمة لاستخدام إعداد Express التلقائي الحالي.

الطريقة المباشرة من Windows:
1) فك ضغط الحزمة في مجلد مثل C:\Nasim-Vercel، وافتح CMD داخل مجلد nasim-vercel-ready الذي يحتوي على package.json وserver.js.
2) نفذ: npm run check
3) نفذ: npx vercel
4) إذا طلب تسجيل الدخول، أكمل تسجيل الدخول بحساب Vercel الصحيح.
5) عندما يسأل عن إعداد المشروع، اختر ربطه بمشروع Vercel الموجود الخاص بنظام النسيم (إذا كان هذا هو المشروع المقصود). لا تنشئ مشروعًا جديدًا بالخطأ.
6) نفّذ النشر التجريبي أولًا. بعد نجاحه اختبر رابط Preview.
7) بعد ضبط متغيرات البيئة واختبار الرابط التجريبي، نفذ: npx vercel --prod

متغيرات البيئة المطلوبة في Vercel Dashboard > Project > Settings > Environment Variables:
- SUPABASE_URL = عنوان مشروع Supabase، مثل https://ncarhiomryekhsbuclvc.supabase.co
- SUPABASE_SERVICE_ROLE_KEY = المفتاح السري service_role الخاص بالمشروع. لا تضعه في الواجهة ولا تشاركه.
- JWT_SECRET = قيمة عشوائية طويلة وفريدة (32 حرفًا أو أكثر). لا تستخدم قيمة تجريبية معروفة.
- NODE_ENV = production

اختَر Production وPreview على الأقل للمتغيرات التي تريد أن تعمل في البيئتين. حفظ المتغيرات وحده لا يغيّر النشر الحالي؛ أعد النشر بعد الحفظ.

اختبار بعد النشر:
1) افتح https://رابط-المشروع.vercel.app/api/health
   يجب أن تكون database = connected و ok = true.
2) افتح الصفحة الرئيسية وسجل الدخول.
3) اختبر عرض القاعات والحجوزات، إنشاء حجز تجريبي، قراءة الدفعات، ثم التقارير والمحاسبة والدعوات.
4) بعد اختبار Preview، انشر Production.

ملاحظات:
- لا ترفع .env إلى GitHub.
- ملف .vercelignore أو إعدادات المشروع لا يجب أن تستثني public/ أو server.js أو package.json.
- Vercel بيئة serverless؛ الملفات المحلية ليست تخزينًا دائمًا. البيانات الأساسية موجودة في Supabase.
- حد طلبات Functions قد يؤثر على رفع ملفات كبيرة. اختبر مرفقات الحجوزات تحديدًا.
- إذا كان المشروع الحالي مرتبطًا بمستودع GitHub، فإن تغييرات مجلد Windows لا تظهر هناك تلقائيًا؛ النشر عبر CLI من هذا المجلد هو نشر مباشر للكود المحلي، أما النشر التلقائي عبر Git فيتطلب رفع التغييرات إلى المستودع.
